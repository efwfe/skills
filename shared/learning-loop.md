# 学习循环:用 → 切 → 造 → 验 → 融 → 沉

sc 的每个命令都是同一个循环的切面。学习者不用记五套流程,只要知道自己在循环的哪一步;每个命令只负责其中几步。

```text
用:先当黑盒用起来        切:找到能切开的缝        造:最小重建
验:和裁判对账            融:换零件、移植到别处     沉:收尾三问,沉淀成 dot
```

| 步 | 做什么 | 产物 | 主要由谁负责 |
|---|---|---|---|
| 用 | 把东西当黑盒用起来:跑通、调旋钮、观察行为,每次先预测 | 预测日志里的几条记录;"它会做什么"的第一版心智模型 | build(先用后造)、repo(阶段 0)、dots(先用一下) |
| 切 | 找到天然的缝,量出开销落在哪 | 零件清单、开销地图、设计决策卡 | repo(地图、追路径)、build(规格书)、dots(最小内核) |
| 造 | 一级只加一个概念,从最朴素的版本建起 | 能跑的代码 | repo、build 的练习模式 |
| 验 | 用能拿到的最强裁判对账 | 测试、对上的输出、复现报告 | repo、build |
| 融 | 把零件换进别的系统,把想法移植到别的项目 | 嫁接实验与移植练习的结果 | build、repo 收尾,dots 的动手练习 |
| 沉 | 回答收尾三问,写进 dot 库 | dot 候选、预测日志、学习记录里的"方法" | 所有命令收尾;dots、graph 负责整理 |

读材料(`sc:blog`)走的是缩短版:用 → 切 → 沉,"造"和"验"由核验原文的数字和例子代替,"融"由迁移题代替。

## 一、用:先当黑盒用起来

拆之前先用。先看见它做了什么,后面的拆解才有问题可问。

- 用最小的输入跑通一次,记下命令、耗时、输出。
- **每次运行前先写下预测**,运行后对照,记进预测日志(第七节)。
- 有可调的参数时,做**旋钮追踪**(第二节)。

## 二、旋钮追踪:从"会用"追到"懂原理"

把使用层和实现层接起来。挑一个使用时能调的旋钮——采样温度、top-p、最大长度、停止词、系统提示、批大小、上下文长度、缓存开关、某个配置项——按四步走:

1. **预测**:调大或调小,输出会怎样变?写下来。
2. **实验**:固定种子,只动这一个旋钮,对比输出(能量化就量化:长度、多样性、准确率、耗时、显存)。
3. **向下追**:它在代码里落在哪几行(`path:line`),经过哪些计算才影响输出?
4. **说清楚**:用一两句话把"现象"和"机制"接上:"温度调高,输出更发散,因为 logits 在 softmax 前被除以温度,分布变平。"

预测与实验不符的地方,就是心智模型要修的地方。

## 三、切:找到天然的缝

一个系统可以从很多地方切开,好的切法让每一块能单独理解、单独替换。

**四类缝**:

| 缝 | 怎么认出来 | 例子 |
|---|---|---|
| 形状或类型在这里变 | 进来的和出去的不是同一种东西 | 文本 → token → 向量 → logits |
| 状态在这里保存 | 有东西跨调用活下来 | 缓存、日志、权重、会话 |
| 控制权在这里反转 | 谁调用谁在这里换了方向 | 调度器、事件循环、回调、训练循环 |
| 开销集中在这里 | 大部分时间或内存花在这里 | 注意力的二次方、热点循环、序列化 |

**切得对不对**:把这一块换成占位实现(恒等函数、固定返回值),系统还能跑通吗?能,说明边界干净;牵一发动全身,说明切在了零件中间。

**切多细**:一块只守一条不变量、只有一个接口时,大小正合适;要用"和"才说得清它做什么,就再切。

**量一量开销**:读代码看的是结构,量开销看的是取舍。用最小输入跑一次,记录每一块的耗时、内存或显存,必要时看中间结果的数值分布:

```bash
python -X importtime -c "import 模块"          # 导入开销
python -m cProfile -s cumtime 入口.py | head -30 # 函数级耗时
```

模型类的用 PyTorch profiler 或在每层前后打印耗时与显存。**开销地图常常直接解释了设计**:某个缓存为什么存在、某个看似多余的拷贝为什么被省掉。量之前先预测开销在哪,记进预测日志。

## 四、造与验

- 造:每级只加一个概念,接口不变,先跑最朴素的版本(见 `sc:repo` 的练习模式与梯级规则)。
- 验:能用强裁判就不用弱的——对上权重的 logits、对上官方输出、对上论文数字、多种子的玩具实验、不变量(见 `sc:build` 的 `references/oracles.md`)。

## 五、融:换零件、移植想法

拆开能装回去不算懂;能把零件换进别处、把想法用到别的项目,才说明真的抓住了它靠什么起作用。

**嫁接实验**(零件层):把 A 系统的一个零件换进 B 系统。

1. 选一处干净的缝(第三节),挑一个可替换的零件:另一种位置编码、注意力、归一化、缓存策略、调度算法……
2. **先预测**:哪些不变量还成立?哪里会坏?输出会偏多少?
3. 换进去运行,对照预测。
4. 写一句结论:这两个零件靠什么接口耦合,换了之后失去了什么、得到了什么。差异往往就是一条张力。

**移植练习**(想法层):挑一个刚学到的 dot,在一个完全不同的项目里用它实现一个小功能。

- 顺利移过去:这个 dot 真的剥离了项目名,给它加一条例证;
- 移不过去:它还依赖原项目的某个前提——把这个前提写进 dot 的"设计面",或把它标成"半个"。

## 六、沉:收尾三问

每个命令收尾都问这三个问题。**用户先答,Claude 再补**;用户说"跳过"就跳过,不劝。

| 问 | 问什么 | 写到哪里 |
|---|---|---|
| 思想 | 这次学到的哪个想法,换个项目也成立?用剥掉项目名的一句话说 | dot 候选(入库走 `/sc:dots`);学习记录"关联的 dot / 候选 dot" |
| 直觉 | 这次哪个预测错了,或结果让你意外?你的心智模型因此改了什么? | 预测日志(第七节) |
| 方法 | 这次用了什么学法最管用(先用后拆、量开销、嫁接、旋钮追踪……)?下次在哪里还能用? | 学习记录的"方法"一节 |

用户的原话记下来,Claude 只补充、不改写。

## 七、预测日志:让直觉可以被测量

直觉就是校准过的预测。每次"先预测再运行"的结果都记下来,时间长了就能看到直觉有没有长进。

位置:dot 库根目录的 `predictions.md`(没有 dot 库时记在本次产物目录里)。只追加,不改旧记录:

```markdown
# 预测日志

| 日期 | 情境 | 预测 | 实际 | 结果 | 修正了什么 |
|---|---|---|---|---|---|
| 2026-10-26 | [[build-reasoning]] 多数投票 | 投 5 次准确率涨 10 个点 | 涨 4 个点,8 次后不再涨 | 偏了 | 收益很快饱和,瓶颈在单次采样的上限 |
```

- **结果**只用三个词:`命中`(方向和量级都对)/ `偏了`(方向对,量级错)/ `错了`(方向就错)。
- **情境**里能链接就用 `[[学习记录或 dot]]`,`/sc:graph --report` 会统计命中率和最近的意外。
- `偏了`、`错了` 的记录是新 dot 和心智模型修正的入口:复盘时优先看它们。
