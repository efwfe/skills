# 写作规范(章节与文章)

## 读者与口吻

- 读者:**只会基础 Python**。假设他会变量、函数、循环、dict/list、用 uv 装包、照着脚本敲;假设他**有终端,会跟着敲**。
- 不假设:PyTorch/tensor、线性代数、概率。这些前置概念要么给"前置知识"框指向附录 A,要么按 §五 的讲解顺序在正文讲透,不要求读者"默认会"。
- 口吻:讲解式第一人称复数(**统一用"我们"**,全文不用"我");不炫技、不吹嘘。
- 结论只下在已验证的事实上;**边界集中写进每章一个"诚实边界"框**,正文不出现"我没验证 / 未验证 / 我没有运行"这类行内免责。
- **不写元文字**:不提 Raschka、不提写作流程、不写"这对应…的思路"——只讲仓库本身。
- 中文行文;术语首次出现给英文原词(`注意力 attention`)和一句话定义,并登记到"本章新术语"框与术语表。
- 叙述声音与句式见 `voice.md`,起草和修订时逐节对照其 §八 自检。

## 章节骨架(模板见 `templates/chapter.md`)

1. **本章要做什么**:3 条要点 + 路线图(当前步高亮)。
2. **前置知识 + 本章新术语**:两个框;术语只在"首次要定义"时列出。
3. **回顾 → 缺口**:上一章已有什么;**现在有什么失败**(真跑给读者看,不是文字描述)。
4. **玩具实例**:数据 ≤ 一页;先纸上手算,再代码复现,两者对得上。
5. **阶梯 L0…Ln**:每级走"一节标准节奏"(见 `pedagogy.md` §三),每节末一句"这个版本还缺什么"。讲过程时的编号与追踪见 `process-narration.md`。
6. **放大到真实配置**:换成仓库的真实参数;打印 shape/参数量。
7. **不变量与对账**:不变量写成显式 `assert`;与原仓库(oracle)同输入比较。
8. **评估/基线**(训练/优化类章节):动手前先量出差距。
9. **设计取舍**:本组件为什么长成这样——一张设计决策卡(问题与约束 / 备选 / 选择与代价 / 证据 / 约束变了会怎样),并给出本组件在贯通表里的一行(思想 / 心智模型 / 架构落点 / 实现落点 `path:line`)。见 `learning-lens.md`。
10. **诚实边界框**:本章唯一的边界集中处(哪些运行过、哪些没有)。
11. **局限**:本章结论成立的条件。
12. **练习**:验证题 + 至少一道"先预测输出再运行",附答案要点;再加一道贯通题(向上收、向下追或改约束,见 `learning-lens.md` §四)。
13. **小结**:要点 + 下一章预告(对应真实章节)。

全部章节写完后,加一章收尾"融会贯通"(模板 `templates/synthesis.md`)。

旁枝框(必要但不属主线的概念)之外,更长的支线放附录 B:正文留结论和指路,细节进 `chapters/appendix-b-*.md`;判断与写法见 `appendix-policy.md`。

## 默认做法(写完逐条自查)

以下是默认做法,破例的条件见 SKILL.md 总原则。

1. **代码必须跑过**:`verify_listings.py chapter.md --fill`,输出由脚本写入,禁止手写或编造输出。
2. **每个代码块 ≤ 15 行**(全库唯一的上限数字),超过就拆成带打印的小步;块前一句"要算什么",块后逐变量解释并写出 **shape**(逐轴)。
3. **先失败后方案**:失败演示必须产生自真实运行(有真实输出),不能只用文字描述;没跑过就不写这个失败。
4. **新概念固定顺序**:直觉 → 极小手算例(纸上+代码各一遍)→ 公式逐个符号解释 → 向量化代码 → 库函数等价性检查(`pedagogy.md` §五)。
5. **一节一个新概念**;出现第二个就拆节。
6. **每次替换实现都对比前一版**(`torch.allclose` / 相等打印)。
7. **随机种子固定**(细则 `references/reproducibility.md`):每个会产生随机的块自带 seed,并写在随机调用之前(`torch.manual_seed(N)` / `np.random.seed(N)` / `random.seed(N)`);跨平台浮点差异用 `torch.allclose(atol=…)` 断言,不逐位相等。
8. **前向引用要落地**:"下一章会讲 X" → 目录里真有 X。
9. **图注是结论句、只写一次**:`![简短 alt](../figures/figN-k.png)` 下一行 `*Figure N.k 结论句*`(见 `figures.md`)。
10. **术语先定义后用**:术语表里没有的术语不得先用;首次出现给定义并登记"本章新术语"框;完整解释过后只回指一次。
11. **事实可溯源**:引用原仓库写 `path:line`;没核对的数字不写,写进"诚实边界"框。
12. **删掉装饰性形容词**("强大的""优雅的");不写"只需几行即可",写"这是 N 行"。

## 反例对照

| 差 | 好 |
|---|---|
| "注意力机制让模型关注重要信息。" | "第 2 个词 `journey` 对 `starts` 的权重是 0.23,对 `one` 只有 0.11(见手算表)。" |
| 直接贴完整的 `MultiHeadAttention` 类 | 拆成投影 → 分组 → 掩码 → 合并四个 ≤15 行的小块,每块断言形状,最后与前一版对账。 |
| "输出类似 tensor([...])" | 真实输出,含 `grad_fn`,再说明为什么有它。 |
| "这块我没验证,先跳过。" | 正文规范讲述已运行的部分;"诚实边界"框里写:"未验证:与真实仓库实现的对账"。 |
| "这对应 Raschka 的骨架先行思路。" | 不讲方法论,直接按骨架 → 替换的叙事写。 |
| "我们/我混用":我写了个包装类。 | "我们先写一个包装类。" |

## 文章(非章节)体裁

用于"方法论/复盘"类单篇文章,结构:
**钩子(一个具体失败或数字)→ 论点 → 3–6 个带证据的小节 → 可执行清单 → 局限**。
证据 = 书/仓库的原句、真实运行数据、图。局限要写。文章不是章节,可提方法论与 Raschka 本人(章节内默认不写)。
