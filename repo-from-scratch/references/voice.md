# 声音与心智模型:书该怎么"说话"

`pedagogy.md` 管**教什么、按什么顺序教**;本文件管**怎么说**。同一个知识点,说明文档式的写法和这本书的写法差别很大。起草和修订时,每一节都对照本文件。

## 一、叙述姿态

我们是**并肩搭东西的老手**,不是站在讲台上的权威,也不是在写手册。读者每一页都在问三件事:我现在在哪?为什么要做这个?做完我能得到什么?每一节先回答它们,再动手。

| 姿态 | 表现 |
|---|---|
| 并肩 | 统一用"我们":"我们先看它会怎么坏。""这一步我们不急着求快。" |
| 交代动机 | 动手前一句话说清为什么需要它,以及没有它会卡在哪 |
| 克制 | 不惊叹、不感叹号、不吹捧;让真实输出说话 |
| 不装懂 | 难的地方直说难,告诉读者先抓什么、可以暂时放过什么(放进旁枝框) |
| 看得见的进展 | 每节结束,读者手里多了一个能跑、能验证的东西 |

## 二、五个心智模型(贯穿全书反复出现,换着场景说)

这五个是**学习方法**的心智模型,每本书都一样。仓库本身的**领域心智模型**(例如"缓存是用空间换重复计算")每本书不同,在阶段 2.5 提炼、写进 `00-scope.md`,由每章"设计取舍"与收尾章"融会贯通"负责(见 `learning-lens.md`)。两类不要混:前者讲"我们怎么学",后者讲"这个系统是什么"。


1. **搭积木,自底向上**:大系统是一堆有明确输入输出的零件;先用最笨的零件把整条线跑通,再逐个换成真的。接口不变,所以随时能跑。
2. **黑盒变白盒**:库里一行调用背后是几行我们看得懂的代码。目标不是造更好的轮子,而是亲手造一次,从此不再怕它。
3. **先跑起来,再变好,最后变快**:正确性、可读性、性能按这个顺序;每次换实现都和上一版对账,打印"一样"。
4. **小处看清,再放大**:在一个能放在手心的例子上把机制看透(能手算更好),再换成真实规模,看变化的只有尺寸。
5. **理解 = 能重建**:读懂一段代码不算懂,能从空文件重新写出来、并让它与原实现吻合才算。

## 三、一个概念怎么讲(从画面到术语)

读者没见过这个词时,按这个顺序,不要倒过来:

1. **画面或场景**:一句话,具体,能想象。("读一句话时,每个词都要回头看看前面有谁值得注意。")
2. **失败**:没有它会怎样,真跑给他看。
3. **名字**:"这个动作有个名字,叫……(英文 ……)。"术语在此刻才出现。
4. **小例子**:几个数字,手算一遍,再让代码算一遍。
5. **一般形式**:公式或完整代码,逐个符号、逐个轴解释。
6. **一句话收束**:"所以 X 做的事,就是……"。

## 四、句子与段落

- 一段只讲一件事,三到五句。长的推导拆成"问题、动作、结果"三小段。
- 先说结论或观察,再给理由。"注意第二行:权重之和是 1。这是因为……"
- 代码块前一句说"要算什么",块后一句说"看这里":指向输出里最该看的那一处,不要复述整个输出。
- 用具体数字代替形容词:不写"显著提升",写"从 {运行前的值} 降到 {运行后的值}"(数字一律取自真实运行)。
- 动词优先,少用被动和名词化:不写"进行一次矩阵乘法的操作",写"做一次矩阵乘法"。
- 译自英文的书面腔要改:不写"值得注意的是""需要指出的是""通过……的方式"。想说就直说。
- 提问可以用,但每节至多一两个,而且要立刻回答。

## 五、固定位置的话

| 位置 | 该说什么 | 一个读起来对的样子 |
|---|---|---|
| 章首 | 现在在全书哪个位置;上一章留下什么缺口;本章要做的三件事 | "上一章我们让模型能说话了,但它每次都从头算一遍。这一章我们给它一个记忆。" |
| 失败演示前 | 预告会坏 | "先不加掩码,看看会发生什么。" |
| 失败之后 | 点出症结,引出方案 | "第一个词已经偷看到了后面的答案。我们需要让它'看不见'后面。" |
| 梯级之间 | 刚解决了什么,还缺什么 | "这个版本对了,但是慢:每个位置都在重复算。下一级我们把它并成一次矩阵乘法。" |
| 对账后 | 一句踏实话 | "两个结果一样。我们的版本和库的版本在数值上等价。" |
| 章末 | 回顾做成了什么;留下的缺口;下一章接什么 | "我们现在有了一个能跑的注意力。它还不会记住过去,下一章补上。" |

## 六、不要这样写

- 营销腔与吹捧:"强大的""优雅的""革命性的""只需几行即可"。
- 权威腔:"显然""众所周知""不难看出""由此可得"。读者不知道时,这些词只会让他觉得自己不行。
- 手册腔:先罗列参数含义,再给示例;读者还不知道为什么需要它。
- 一口气三个新概念;同一个解释换着说法重复。
- 把边界散在正文里道歉:"这里我没验证"。边界集中放进"诚实边界"框,正文只说做过的事。
- 书里不提写作方法、不提别的书或作者(那是写给你的内部说明,不是写给读者的)。

## 七、对照改写

**讲 softmax**

> 说明文档式:softmax 函数将实数向量映射为概率分布,其定义为 exp(x_i) / Σ exp(x_j)。
>
> 这本书的写法:模型给三个候选词打了分:2.0、1.0、0.1。分数不能直接当概率,因为它们加起来不是 1,还可能是负数。我们想要一个办法,让分高的占更大的份额,总和刚好是 1。先手算:把每个分数取指数,得到 7.39、2.72、1.11,加起来 11.22;各自除以 11.22,得到 0.66、0.24、0.10。这个办法叫 softmax。下面让代码算一遍,看是否一样。

**讲因果掩码(章首与失败)**

> 说明文档式:为防止信息泄露,需要对注意力矩阵施加因果掩码。
>
> 这本书的写法:现在每个词能看到整句话,包括它后面的词。训练时这是作弊:预测第 3 个词,却偷看了第 4 个词。我们先让它作弊给你看。(代码、输出)你看第一行:第 1 个词对第 4 个词的权重是 {真实输出里的非零值},它本不该知道第 4 个词存在。(花括号处在书里一律填运行得到的真实数字。)

**讲一个梯级之后**

> 说明文档式:至此,实现已完成。
>
> 这本书的写法:这个版本对了,而且我们可以证明它对:输出和上一版逐位相等。它还慢,每个位置都重算了一遍前面的东西。下一级我们把重复的部分存起来。

## 八、声音自检(起草后、审稿前)

1. 随便挑三个段落:每段能否用一句话说出"这段让读者多懂了什么"?不能就删或并。
2. 每个术语出现前,读者是否已经见过画面或失败?
3. 把所有"的、了、地"以外的修饰词标出来:有多少是形容词、副词?能换成数字就换成数字。
4. 每一节结尾,读者是否知道"还缺什么"?
5. 大声读章首和章末:像一个人在说话,还是像在念说明书?

## 九、规则与读者的优先级

读者看得懂 > 声音好听 > 形式整齐。句式和"固定位置的话"是参考样板,不是填空模板;不是每章每节都得套一遍。
