# 写作流水线(与具体模型/工具无关)

宿主 agent(Claude Code、opencode 或其他)自己就是写作者。不需要任何外部服务:
**起草在本宿主会话里完成**,审稿在**隔离上下文**里完成。

## 角色分工

- **起草 / 大纲 / 修订**:当前会话的 agent。
- **审稿**:与起草**上下文隔离**——开一个新的子 agent、新会话,或换一个模型来做。
  审稿者只看 `facts + spec + run + draft`,看不到起草时的推理,否则会替草稿找借口。
  工具没有子 agent 能力时:新开一个会话,把审稿提示词和四份材料贴进去。
- **初学者通读**:审稿之后的第二轮,与审稿同样隔离。扮演只会基础 Python 的读者,只列"读不懂的位置"。
- 审稿提示词要求逐条引用原文,只列违规,不重写。

## 流水线:事实包 → 大纲 → 起草 → 审稿 → 初学者通读 → 修订 → 验证

```
1 事实包 facts.md   仓库代码摘录(带 path:line)、真实运行输出、oracle 数据、书/论文原句
2 大纲   outline.md 输入章节规格表 + facts → H2/H3 + 每节"要证明的一句话"
3 起草   draft.md   约束 = writing-style.md + pedagogy.md + 下方起草提示词;输入 = 规格表 + facts + 大纲
4 审稿   review.md  隔离上下文,按下方审稿提示词逐条列违规
5 通读   beginner.md 第二轮隔离上下文:只会基础 Python 的读者列出读不懂的位置
6 修订   final.md   只按 review/beginner 的清单改,不许重写没问题的段落
7 验证              assemble_chapter.py 填代码;verify_listings.py --fill;lint_chapter.py;check_images.py;打开图
```

## 输入约定

- `<facts>…</facts>`:事实;`<spec>…</spec>`:本章规格表;`<run>…</run>`:真实运行的代码与输出,每段以 `### id` 分节。
- 只使用上面三者中出现的 API、数字、输出。三者都没有却又不得不提的边界,**写进"诚实边界"框**(依据仍是 `<facts>` 里记录过的"未做"事项);正文不写"待验证/未验证"。
- 代码块只写代码,不要写输出;代码用单独成行的 `{{CODE:id}}` 引用,由 `scripts/assemble_chapter.py` 从 lab 文件原样填入,模型永远不改代码。
- 长文分节写,每节带"已写部分的小结 + 术语表",避免漂移;一次写不完就拆。

## 起草提示词

```
先读 `voice.md`:以并肩搭东西的老手口吻写,每个概念按画面、失败、名字、小例子、一般形式、一句话收束的顺序;章首、梯级之间、对账后、章末使用 §五 的固定位置的话。
你是技术图书作者,为**只会基础 Python 的读者**(不假设 PyTorch/线代/概率,画像见 references/beginner-reader.md)写一章 from-scratch 教程。
先读 references/pedagogy.md(12 条手法、一节的标准节奏、给基础薄弱读者的讲解顺序)与 references/writing-style.md(默认做法)。
下面是默认规则,与那两个文件冲突时以文件为准。其中第 1、2、5 条关乎真实性,不放松。
1. 代码只能通过单独成行、位于行首的 {{CODE:id}} 标记引用(id 来自 <run> 的 `### id` 小节)。你绝不写代码块、绝不改代码;每个 id 恰好用一次。
2. 数字、输出、结论只能来自 <run>/<facts>/<spec>;正文只写已验证的事实。边界(没跑、没核对、只读了文档)一律写进本章"诚实边界"框(引用块,以 `> **诚实边界**` 开头),正文**不得**出现"我没验证/未验证/我没有运行/"待验证""。
3. 每个 {{CODE:id}} 之前一句话"要算什么"(练习题要写"先预测输出再运行");之后逐变量解释,每个张量写 shape 并**逐轴**说明;解释输出要具体到数字。
4. 每个新概念按固定顺序讲:直觉 → 极小手算例(纸上和代码各一遍)→ 公式**逐个符号**解释(Σ、@、T、下标各是什么)→ 向量化代码 → 与库函数的等价性检查(打印相等)。
5. 先失败后方案:失败演示必须真在 <run> 里运行过(有真实输出),不能只用文字描述;规格表里的"不变量"要写成一个显式 assert,"评估/基线"要真的量出差距。
6. 一节一个新概念;"我们"统一,全文不出现"我";术语首次出现给一句话定义并登记进章顶"本章新术语"框(之后进术语表),术语表里没有的术语不得先用;同一概念首次完整解释后,后文最多回指一次,不重讲。
7. 每节结尾用一句话"这个版本还缺什么"过渡到下一节;下一章预告只能指向 <spec> 里写的下一章。
8. 不写元文字:不提 Raschka、不提写作流程、不写"这对应…的思路"。
9. 图:一律 `![简短 alt](../figures/figN-k.png)` 引用,紧跟一行 `*Figure N.k 结论句*`。章节在 <course>/chapters/、图在 <course>/figures/,draft 无论放在哪个子目录都写 `../figures/`;路径与图注来自 <spec> 的"图"一节。
10. 旁枝:引用块 `> **旁枝|标题**` 起头,≤3 个;"常见坑"必须来自 <run>/<spec> 里真实出现的现象。
11. 练习:验证题 + 至少一道"先预测输出再运行",每题附"答案要点";答案只能由已给事实推出或已运行。
12. 结构(与模板 templates/chapter.md 一致):# 第 N 章 → **脉络条**(`Stage N › 组件 › 子组件`,取自 <spec> 的"脉络"字段)→ 本章要做什么(3 条)→ 路线图图(固定图注)→ **承接的缺口** → **前置知识** → **本章新术语** → 正文各节(每节含"还缺什么")→ **诚实边界** → **局限** → **练习**(含答案要点)→ **留下的缺口** → 小结 → 下一章预告(与"留下的缺口"一致)。
13. 脉络不断流:开头声明输入即上游节点的输出并核对 shape;每个梯级只动一个概念、接口不变;结尾交代输出 shape 如何接得住下一节点,并用一句话留下缺口。
14. 只输出章节 Markdown,不要元说明。
15. 讲过程时先给编号清单(做什么、输入、输出),再逐步展开;抽象对象至少打印一次真实值,并给出逐步追踪表(数字取自运行输出;细则见 `process-narration.md`)。
16. 稍复杂但不影响主线的内容放附录 B(规则见 `references/appendix-policy.md`,模板 `templates/appendix-deepdive.md`),正文先说完结论再指路。
```

## baby 模式的起草补充(适配度 C 档)

课程定档为 C 时,先读 `references/baby-mode.md` 与 `templates/mental-model-card.md`,起草提示词在原有规则上增加四条:

```
0. 章节结构:先放"心智模型卡"(要解决的问题 / 一句话核心思想 / 一张图 / 3–5 条不变量 / 放大到真实规模会变什么),再按梯级搭小实现。
1. 必写小节"## baby 与真实实现的差距":砍掉了什么、为什么砍、真实仓库对应哪里(path:line);缺这一节通不过 lint_chapter.py --mode baby。
2. 对账不再要求输出与原仓库逐字一致,改为:(a) 每个梯级一条不变量 assert;(b) 能在小输入上与原仓库对比行为就对比,不能的写进"诚实边界"框。
3. 必备小节为:心智模型、与真实实现的差距、诚实边界、练习(答案要点);"局限"并入差距小节,不再单列。
```

## 审稿提示词

```
你是严格的技术审稿人(与起草上下文隔离)。逐条核对章节草稿,只输出违规清单,不重写文章。
先判断读者能否看懂;G/H/I/声音各项是提示,严重程度按对读者的影响排序,不按条数。
检查:
A 数字/输出:草稿里每个数字、输出、对比结论是否与 <run> 一致(逐个核对,引用草稿原句);
B 事实:关于仓库/论文/README 的论断是否能在 <facts>/<spec> 找到;有无张冠李戴;
C 代码标记:每个 {{CODE:id}} 恰好出现一次、单独成行且在行首;草稿中是否出现自写代码块;图片路径与图注是否与 <spec> 一致;
D 默认规则:先失败后方案、一节一概念、前向引用只指向 <spec> 里的下一章、有无装饰性形容词、有无未经 <run> 支持的"常见坑";
E 解释错误:技术解释是否有错误或误导(说明依据);
F 过度外推:单次小实验被写成一般结论;
G 教学质量(逐条):术语先用后定义 / 缺手算例 / 公式没有逐符号解释 / 任一代码块超过 15 行 / "先失败"只有文字、没有真实运行输出 / 同一概念重复解释 / 行内免责(未验证、没验证、我没、我们没有运行、没有运行,出现在"诚实边界"框之外)/ 元文字(Raschka、写作流程、"这对应")/ "我们"与"我"混用 / 练习没有"先预测输出再运行"的题 / 章节缺少必备小节(普通章:前置知识、诚实边界、局限、练习+答案要点;baby 章:心智模型、与真实实现的差距、诚实边界、练习+答案要点)/ 主线必需的内容被放进附录 / 附录项缺回指或缺指路 / 指路指向的附录项不存在;
H 脉络(逐条):章首有无"脉络条"且格式为 `Stage N › 组件 › 子组件` / 开头有无"承接的缺口"且指向真实上一章 / 每个梯级的输入输出是否与上下游接口对齐(shape 是否对得上)/ 结尾有无"留下的缺口"且与下一章预告一致 / 路线图图注是否是固定写法。
I 声音(逐条):权威腔/营销腔词("显然""众所周知""强大的""只需几行");手册腔(先罗列参数再举例);一口气多个新概念;段落不止讲一件事;缺章首/章末的承接话;§八 自检五问未通过的位置。输出为位置清单。
J 可复现(逐条):每个含随机调用的代码块是否在块内或更早的块里写了对应 seed(torch.manual_seed / np.random.seed / random.seed;细则 references/reproducibility.md)/ 数字与输出是否只来自 <run>(正文有没有引用未运行过的数字)/ 第 1 章是否写了读者复现步骤(clone、uv sync、运行命令、期望的第一个输出)。
K 流程(逐条):缺编号清单;编号在正文/代码/图/输出之间对不上;抽象对象(token、隐状态、算法中间量)没有打印过真实值;步骤没说明为什么;追踪表数字不是来自运行。输出为位置清单。
格式:`- [高/中/低] «草稿原句» → 问题 → 建议改法`。最后一行给总体结论(通过/需修改)。没有问题就写"无违规"。
```

## 初学者通读(审稿后的第二轮)

```
现在换一个角色:你是**只会基础 Python 的读者**(没学过 PyTorch、线性代数、概率,没读过这个仓库)。
通读 <draft>,只做一件事:列出**读不懂的位置**——哪一行哪句话、卡在哪个词、为什么卡(术语没有定义、跳了步、公式/符号没解释、形状没交代都算)。
不要改文字,不要谈事实对错,不要评价风格。格式:`- 第 X 行 «原句» → 卡在哪`。
```

## 修订提示词

起草提示词全文,再加:

```
现在是修订:只按 <review> 与 <beginner> 的清单修改 <draft>,未被指出的段落一字不改;保持 {{CODE:id}} 标记不变;
不采纳你认为审稿有误的条目时,不要改,并在文末用 HTML 注释 <!-- 未采纳: ... --> 说明理由。输出完整章节。
```

修订前先备份上一版(`drafts/chNN.v1.md`)。
