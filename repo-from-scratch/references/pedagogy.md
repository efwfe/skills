# Raschka 教学法:《Build a LLM From Scratch》拆解

> 来源:370 页全书通读 + 第 2–5 章逐段精读 + 版式截图。引用均为短句,章节号为原书章节号。
> 结论先行:这本书好,不是因为"讲得全",而是因为**每一步都可运行、可验证、可手算**,
> 且**顺序遵守"先失败、再简化、后真实"**。

## 一、全书骨架:三阶段 / 九步路线图

| 阶段 | 步骤 | 对应章 |
|---|---|---|
| 1 构建 | 1 数据准备与采样 · 2 注意力 · 3 LLM 架构 | ch2 / ch3 / ch4 |
| 2 预训练 | 4 预训练 · 5 训练循环 · 6 评估 · 7 加载权重 | ch5 |
| 3 微调 | 8 分类微调 · 9 指令微调 | ch6 / ch7 |

- 同一张路线图在每章开头重复出现,当前步骤高亮。读者永远知道"我在哪、前面做了什么、后面是什么"。
- 每章三段式开头:**本章要做什么**(要点)→ 回顾上一章成果 → 路线图高亮。
- 每章三段式结尾:小结(要点列表)→ 练习 → 下一章预告。

## 二、12 条可迁移的教学手法

### 1. 先说"没有它会怎样"(失败驱动)
讲注意力前先讲 RNN 编码器-解码器只有一个隐藏状态的瓶颈,再讲 Bahdanau 注意力,最后才是 self-attention。
→ 每个组件之前,先给读者一个**它要解决的具体失败**,而且要能跑给读者看。

### 2. 自顶向下搭骨架,自底向上填零件
先写 `DummyGPTModel`:`DummyTransformerBlock.forward` 只 `return x`,`DummyLayerNorm` 同理。
骨架已经能跑,然后按编号图逐个替换占位符。
→ 任何时刻项目都是绿的;读者先看见全貌,再看细节。

### 3. 简化 → 真实的阶梯(每级是上一级的 drop-in)
注意力四级:无权重简化版 → 带可训练权重 → 因果掩码 → 多头。类也是阶梯:`SelfAttention_v1` → `v2` → `CausalAttention` → `MultiHeadAttention`。
→ 每一级只引入**一个**新概念,且保持接口不变。

### 4. 一个极小实例,贯穿到底,可手算
`"Your journey starts with one step"`:6 个 token × 3 维,小到能印在一页上。先算一个 query,再嵌套循环算全部,最后矩阵乘法。
→ 读者可以拿纸笔核对;图里的数字截断到一位小数并在图注里声明。

### 5. 三段式实现:循环 → 向量化 → 库函数
点积:先 `for` 循环累加,再 `torch.dot`,打印两者相等。softmax:先 naive 版说明数值溢出,再 `torch.softmax`。
→ **先明白在算什么,再用高效实现**;每次替换都做等价性验证。

### 6. 形状是一等公民
`probas.shape → torch.Size([2, 3, 50257])`,紧接着逐轴解释:2 是 batch,3 是 token 数,50257 是词表。
→ 每个关键张量都写出 shape 并解释每一维。

### 7. 数学技巧讲"为什么成立"
先 softmax 再置零 vs. 先填 `-inf` 再 softmax:解释 `e^(-inf) → 0`,所以无未来信息泄漏且只需一步。dropout 乘 `1/0.5` 保持期望。
→ 不只给代码,给**不变量**,并写成可运行的 `assert`。

### 8. 概念清楚后才放大规模
全书前期用 3 维、6 个 token;第 4 章才切到真实配置(768 维、12 层),并逐字段解释 config。
→ 小实例学原理,真配置学工程。

### 9. 评估先行:先量出差距,再训练
未训练模型的输出与目标并排打印,再复用生成流程推导 loss,补 perplexity = exp(loss)。
→ 训练前先有**基线和度量**,读者能"看见"训练在改善什么。

### 10. 诚实的现实校准
"单卡训练 GPT-3 要 355 年";因此在小数据集上教学性训练,并加载开源权重拿到真实效果。
→ 承认规模差距,给出可完成的替代路径,不吹牛。

### 11. 旁枝用"框"隔离,主线不被打断
超纲内容放进灰框并声明范围,主线只留必要概念。
→ 主线只留必要概念;旁枝可选读。更长的支线放附录 B,见 `appendix-policy.md`。

### 12. 练习是"验证题",不是"开放题"
"把 v2 的权重迁移到 v1,证明两者等价"、"数 FFN 与注意力参数量"。每题都有可检验的答案。
→ 练习 = 一次对"我真的懂了"的断言测试。

## 三、一节的标准节奏(从单节抽象)

```
[一句话目标: 这一节我们要算出 ___]
 → [图: 步骤框 1→2→3,右侧灰色旁注,图注写结论]
 → [最小代码块 (≤15 行) + 真实输出]
 → [逐行/逐变量解释: 它在算什么、shape 是什么]
 → [与上一版结果对比: 相等 / 为何不同]
 → [下一步的问题: 这个版本还缺什么?] → 下一节
```

节内的具体话术见 `voice.md` §三(从画面到术语的概念讲解顺序)与 §五(章首、梯级之间、对账后、章末等固定位置该说的话);手法本身不因声音而变。节里讲的是有先后顺序的过程(一次前向、一个算法、一条数据流)时,编号与逐步追踪的做法见 `process-narration.md`。

## 四、版式规范(书的外观)

- 代码:带编号 Listing,正文已解释的地方删注释。
- 输出紧跟代码块,真实运行结果,不省略 `grad_fn` 之类细节(教学诚实)。
- 图:见 `figures.md`;图注写结论句。书内图注在 Markdown 里写一次(见 `figures.md` 的规范)。
- 随机种子固定(`torch.manual_seed` / `np.random.seed` / `random.seed`,写在随机调用之前的那个点,细则 `reproducibility.md`),任何一章可复现。

## 五、给基础薄弱读者(迁移时要补的东西)

原书默认读者懂一些线性代数与 ML。我们明确把读者定位为**只会基础 Python**,因此每条主线叙述都要遵守下面五条(详细规则见 `writing-style.md`,读者盘点流程见 `beginner-reader.md`)。

1. **新概念的固定讲解顺序**(不可跳步):
   直觉 → 极小手算例(先纸上、再代码各一遍)→ 公式(**逐个符号**解释:Σ、`@`、`T`、下标分别是什么)→ 向量化代码 → 与库函数的等价性检查。
   例:讲 softmax,先说"把一组数变成正数、和为 1 的权重",再手算 3 个数,再写公式逐个解释指数与分母,`.exp()` 向量化,最后与 `torch.softmax` 对账打印相等。
2. **前置知识框**:每章开头写"前置知识"(指向附录 A 第几节或前一章),正文不假设读者凭空会。
3. **术语先定义后用**:术语首次出现给一句话定义,登记到该章顶部"本章新术语"框与全书术语表;**术语表里没有的术语不得先用**。同一概念首次完整解释后,后文只回指一次("见 2.3 的 softmax"),不再重讲。
4. **练习含"先预测输出再运行"**:至少一道题要求读者先写下预期输出,再运行核对,并附答案要点。
5. **诚实边界集中放置**:正文只陈述已验证的事实;所有"没跑、没验证、没核对"的边界写进该章唯一的"诚实边界"框,正文里**不出现**"我没验证/未验证"这类行内免责(原书多处"does not violate"式的行内免责在这里改为集中说明)。

## 六、值得警惕的局限(迁移时别照抄)

- 全书线性、单仓库、单语言;换成别的仓库要先做**依赖分层**(见 `repo-dissection.md`)。
- 书偏教学,极少讲工程取舍(分布式、混合精度、kv-cache);迁移时在"工程篇"单列,别塞进主线。
- 书里大量前向引用 —— 迁移时每个前向引用要落在真实章节上,否则删掉。

## 七、每个组件的脉络(全局与局部)

每章是全书脉络树上的一个节点,两条脉络同时遵守(细则与脉络条格式见 `references/narrative-structure.md`):

1. **全局不迷路**:章首第一行写脉络条(`Stage N › 组件 › 子组件`),随后放两级路线图之一(图注固定写法见 `figures.md`);每个 stage 的第一章放 stage 级整树,其余章放组件级小图。
2. **五步不断流**:承接缺口 → 问题与先失败(真实运行)→ 构造梯级 → 接口对齐(输入 = 上游输出、输出接得住下游,写着 shape)→ 留下缺口。
3. **两处必填**:章首"**承接的缺口**"(第一节之前)、小结前"**留下的缺口**"(与下一章预告一致);空白断言 = 读者断流。
4. **接口先声明再解释**:每个梯级第一句先给出输入输出 shape,说明它接的是谁的输出、交给谁,再讲内部。
