# 图的绘制规范(取自书的版式 + 可复现工具)

## 先问:这里需要图吗?

每个**数据流/步骤/形状变化/依赖关系**配一张图;纯定义不配。书平均每 1.5 页一张图。
图的任务是**让读者在读代码前先看到过程**;图注写**结论**,不写标题。

## 书的图的 8 个特征

1. **扁平**:白底框、1px 深色描边、圆角小;无渐变、无阴影、无 3D。
2. **步骤图**:竖排框 + 向下箭头,框内标 `1) 2) 3)`;右侧灰色粗体旁注,虚线箭头指回框。流程图箭头旁标执行顺序编号(①②③),与正文、代码注释、输出里的编号一致;分支用 ②a/②b(细则见 `process-narration.md` §二)。
3. **路线图**:两级——stage 级(全书脉络树,当前 stage 高亮并展开组件链)与组件级(stage 固定、当前组件高亮);每章开头画当前级,当前位置淡黄高亮。
4. **数字矩阵**:真实数值,截断到 1–2 位小数,图注声明"数字已截断"。
5. **掩码/未来信息**:被屏蔽格用浅灰;上三角画空(掩码前后对比)。
6. **颜色克制**:只用一个高亮色标"当前关注点";其余黑白灰。
7. **对照图**:同一图里并排"之前/之后"。
8. **图注 = 一句完整结论**:写在 Markdown 里(见下),不在图内。

## 图类型 → 何时用 → figkit 方法

| 图 | 用于 | 方法 |
|---|---|---|
| stage 级路线图 | 每个 stage 的第一章开头:整棵树,本 stage 高亮、展开组件链 | `Fig.roadmap_tree(stages, current, chain)`,chain 元素可为 `(label, [子组件…])` |
| 组件级小路线图 | stage 内每章开头:stage 固定,当前组件高亮 | `Fig.roadmap_chain(items, current, stage=, up=, down=)` |
| 步骤链 + 旁注 | 一个算法的 2–5 步 | `Fig.steps(...)` |
| 数值矩阵 / 热图 | 注意力权重、掩码、混淆矩阵 | `Fig.grid(..., hi=, blank=)` |
| 框图/分层架构 | 模块嵌套 | 多个 `Fig.box` + `Fig.arrow` |
| 数据流 shape 图 | `[B,T] → [B,T,C]` | `box` 内写 shape,`callout` 写含义 |
| 条形图 / 折线图 | 构成比例、曲线 | `Fig.bars` / `Fig.lines`(常数列与平台线用不同线型) |
| 依赖图 | 仓库 import 分层 | `repo_map.py` 输出 → 手工用 `box` 分层 |

## 工作流

```python
from figkit import Fig          # 把 skill 的 scripts 目录放进导入路径(书的 make_figures.py 里用 __file__ 定位)
f = Fig(640, 300)
f.steps(40, 20, ["1) Compute scores", "2) Softmax", "3) Weighted sum"],
        ["dot products", "rows sum to 1", "context vectors"])
f.save("<course>/figures/fig2.svg")     # 同时产出 fig2.png
```

1. **先在纸上定图的结论句**(图注),再画。
2. 数值图的数据来自真实运行输出,不手填。
3. `save()` 写入前做两件事,失败即抛错、不会默默产出坏图:
   - **边界检查(`check()`)**:任何元素(按估算外框)超出画布或文字超出所在框都会报错,而不是静默截断;
   - **SVG 合法性校验**:把生成的 SVG 解析一遍,不是合法 XML 就拒绝写入。教训:曾因 `font-family` 属性值里嵌套单引号,一次性生成了 29 个非法 SVG,Chrome 把每个都渲染成报错页。**写 SVG 属性时,内层引号一律用 `&quot;`**(figkit 的字体栈就是这么写的),别把单引号套进单引号。
4. PNG 回退链:headless Chrome(2 倍缩放,SVG 直接加载)→ `rsvg-convert` → `qlmanage`(+`magick -trim` 去边);三者都没有时只保留 SVG 并打印提示。教程里不要自行改这条链,也不假设读者用哪个操作系统。
5. `save()` 后**打开 PNG 逐张检查**:文字不截断、不重叠、箭头不糊成一团(多个箭头先落到同一目标时用 `Fig.fan(...)` 分散落点)、正文字号 ≥ 11px;路线图(stage 级与组件级)总宽 ≤ 760、字号 ≥ 13,放不下就删词或换更短标签,不要缩字号。

## 图注与引用路径(全书统一)

- 章节在 `<course>/chapters/`,图在 `<course>/figures/`;引用一律写 `../figures/`(drafts/、specs/ 里也是这个写法,按相对 md 文件所在目录解析)。
- **图注只在 Markdown 里写一次**:`![简短 alt](../figures/figN-k.png)` 紧跟下一行 `*Figure N.k 结论句*`;alt 写简短描述,PNG/SVG 图内**不再带图注**(`Fig.caption()` 只作调试用)。
- **路线图图注固定写法**(两级通用):`*Figure N.1 第 N 章在全书路线图中的位置(高亮)*`,高亮的是本 stage 还是本组件,由正文第一句点明;章内第一张图占 N.1。
- 结论句引用书里"过"的数字时,与正文一致;数字截断要声明。

## 复杂图 / 想要更精致

- 架构图(云、网络):用现成 skill `architecture-diagram`(深色主题 HTML+SVG)。
- 数据图表:用 `dataviz` skill。
- 这两者风格与书的"扁平黑白灰"不同;同一篇文章内不要混用,选一种。

## 已知限制

- SVG 里的中文依赖本机 CJK 字体;跨机器复现时优先装(或指定)Noto Sans CJK SC。PNG 由 SVG 生成,不上传、不依赖任何渲染服务。
- `text_width()` 是按字符类别的估算(CJK 约 1em、拉丁约 0.55em),边界检查是守门不是排版;最终以打开 PNG 为准。
