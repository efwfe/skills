# 抽丝剥茧:把任意 GitHub 仓库拆成 from-scratch 课程

目标:不是"读懂这个仓库",而是**从空文件夹出发,自己把它重新长出来**,并证明长得和原仓库一致。
书里的方法(见 `pedagogy.md`)是在一个已知架构上做的;这里把它变成对**未知仓库**可重复的流程。
读者只会基础 Python(`beginner-reader.md`)——任何一步都不能假设读者会本仓库领域的专用知识。

## 阶段 0 — 定义"这个仓库到底干什么"(30 分钟)

1. 读 README、LICENSE、`pyproject/package.json/go.mod`。
2. **把它跑起来**(最小命令),记录:命令、耗时、输出。跑不起来就先别写。
3. 写下三句话(后面所有章节都要对得上):
   - **一句话**:它把 ___ 变成 ___。
   - **黄金路径**:输入 X → 经过哪几步 → 输出 Y(一条端到端的最小调用)。
   - **终点演示**:读者学完后能亲手跑出什么。

## 阶段 0.5 — 适配度评估(定档)

跑通之后、画地图之前,回答 `references/fit-assessment.md` 的五问,答案写进 `00-scope.md` 的"适配度评估"一节,定档:

- **A 完整从零**:五问基本满足,走阶段 1–8 全流程,输出与原仓库同输入对账。
- **B 内核从零 + 其余导读**:只对判定为"本质"的组件走阶段 3–7;仓库其余部分(工程/扩展)带注释导读,不重建。
- **C baby 版**:停用阶段 1–8,改走 `references/baby-mode.md`:心智模型卡 + 小实现 + 每章"与真实实现的差距"小节。

档位有争议时先问用户,不自己硬选;选 B/C 时,每章"诚实边界"框必须写明哪些部分没有从零重建、为什么。

## 阶段 1 — 地图(`scripts/repo_map.py`)

```bash
uv run python skills/repo-from-scratch/scripts/repo_map.py <repo_dir>
```

输出入口、被引用最多的文件、最大文件、import 分层(L0 = 叶子)。据此判定:

| 类别 | 判断 | 课程里的位置 |
|---|---|---|
| **本质(essence)** | 删掉它,黄金路径失败 | 主线章节 |
| **工程(engineering)** | 配置、CLI、日志、分布式、兼容层、缓存 | "工程篇"/附录,主线用硬编码代替 |
| **扩展(extension)** | 可选后端、插件 | 练习题 |

> 例(nanoGPT,1220 LOC):`model.py`(330 行,L0,被 3 个文件引用)是本质;`train.py`、`sample.py` 是 L1 的两个入口;
> `configurator.py`、`config/*`、`data/*/prepare.py` 是工程/数据准备。(其余章节的示例请换成读者所在领域的最小例子,如一条 HTTP 报文、一个表达式。)

## 阶段 2 — 追黄金路径(插桩,不是读代码)

- 用最小输入运行,在每个关键函数边界打印:**名字、输入 shape/类型、输出 shape/类型**。
- 产出一张**数据流脊柱**:`A(x) → B(→…) → C → ...`。这就是课程的章节顺序候选。
- 对每个节点做**删除实验**(ablation):注释掉/换成恒等函数,看什么坏。坏得越明显,越是本质。
  这一步等价于书里的 `DummyTransformerBlock`:证明骨架不依赖零件,零件各自可替换。

## 阶段 3 — 洋葱剥皮:阶梯设计

对每个本质组件,设计 3–5 级阶梯,每级只引入**一个**新概念,且接口不变,每级由 ≤15 行的小代码块组成:

```
L0  玩具版:无参数 / 无优化 / 硬编码,能手算
L1  真实数据结构:加上可训练/可配置的部分
L2  真实语义:加上约束(掩码、边界、错误处理)
L3  真实形态:批量化/并行化/向量化
L4  规模与性能:换成仓库的真实配置与库函数
```

规则:
- 每级必须与上一级结果对比(相等或解释为何不同)。
- 最后一级的输出必须与**原仓库同输入下的输出**对比 —— 原仓库是**预言机(oracle)**。
- 某级若引入 ≥2 个新概念,拆开。

## 阶段 4 — 读者阶梯与前置盘点(写规格表前必做)

读者只会基础 Python。把全书(每个 L 梯级、每个公式符号、每次库调用)将用到的**所有前置概念**列出来,三分;盘点时把"稍复杂但不影响主线"的内容单独列出,按 `appendix-policy.md` 判断是否放附录 B:

| 去向 | 条件 | 做法 |
|---|---|---|
| 该章正文/旁枝 | 只被一章使用 | 仍是"先定义后用",讲完定义即可 |
| **附录 A + 术语表** | 被 ≥2 章使用 | 附录 A 开一节(可运行代码,模板 `templates/appendix-basics.md`)+ 术语表一条 |
| 第 1 章 | 全书脚手架(梯级、对账、诚实边界的读法) | 第 1 章讲透,后文只回指 |

产出:**前置阶梯清单**(格式见 `references/beginner-reader.md`)与**术语表初稿**。
门禁:每个多章复用的概念在附录 A 有可运行小节;每个术语有定义句;读者从第 2 章起遇到的每个术语,要么已定义,要么在当章"本章新术语"框(`lint_chapter.py` 自动核对首次使用)。

## 阶段 5 — 章节顺序

1. 先画**路线图**(每章标出高亮步骤);第 1 章讲读者定位、前置知识、如何读这本书(梯级/对账/诚实边界)。
2. 第 1 章后立刻给**骨架**(`Dummy*` 占位,端到端能跑、输出无意义但形状正确)。
3. 之后按 **import 分层自底向上**填充零件(L0 先),每章结束时骨架里少一个 Dummy。
4. 评估/度量**先于**训练/优化类章节出现(先量出差距再动手)。
5. 真实结果靠**加载原仓库权重/数据**获得,而不是自己烧算力。

## 阶段 5.5 — 画全书脉络树

按 `references/narrative-structure.md` 的全局层画:stage → 组件 → 子组件;每个节点标注"上游给我什么 / 我做什么 / 我交给下游什么";依赖写成"A 的缺口 → B 来填"。树写进 `00-scope.md` 的"全书脉络树"一节,每章一个节点,章序即树的遍历序。每章规格表的"脉络"字段从树里抄。

## 阶段 6 — 每章规格表(写作前先填)

| 字段 | 内容 |
|---|---|
| 脉络 | 所属 stage / 上游输入(shape)/ 下游输出(shape)/ 承接上一章的缺口 / 留给下一章的缺口(对应 `narrative-structure.md` 的局部层五步) |
| 位置 | 路线图第几步;依赖哪章;产出哪个类/函数(替换骨架里哪个 Dummy) |
| 失败动机 | 没有它,上一章的东西哪里不行(**要能演示、能运行**) |
| 玩具实例 | 数据 ≤ 一页;写出手算期望值 |
| 阶梯 | L0…Ln 各自新增一个概念 |
| 不变量 | 要证明的性质(行和为 1;未来无泄漏;参数量 = ?)——**必须能写成一个 `assert`,模板与起草提示词都据此要求** |
| Oracle 对比 | 原仓库哪个函数、哪个输入、比较什么(`allclose`/逐字符/hash) |
| 评估/基线 | 训练/优化类章节:动手前先量出什么差距(非此类章节省略) |
| 前置知识 | 指向附录 A 第几节 / 前一章;本章新术语清单 |
| 旁枝框 | 必要但不属主线的概念(≤3 个) |
| 练习(验证题) | 每题带可检验答案;至少一题"先预测输出再运行" |
| 常见坑 | 实测遇到的报错/数值问题 |

## 阶段 7 — 对原仓库做对账

- 建 `oracle/` 目录:固定随机种子,保存原仓库对若干输入的输出(npz/json)。
- 每章末尾有一个 `assert` 与 oracle 对比;**不一致就修教程,不改 oracle**。
- 差异分类:`数值误差(允许,给 atol)` / `实现差异(解释)` / `我错了(修)`。

## 阶段 8 — 不同类型仓库的"脊柱"提示

| 仓库类型 | 脊柱通常是 | 玩具实例 | 终点演示 |
|---|---|---|---|
| ML 模型/训练 | 数据 → 张量 → 模块 → loss → 循环 | 6 个 token × 3 维 | 生成/分类 |
| Web 框架/服务器 | 字节流 → 请求 → 路由 → 处理 → 响应 | 一条 raw HTTP 报文 | `curl` 得到响应 |
| 数据库/存储 | 写入 → 日志/页 → 索引 → 查询 | 5 条记录 | 崩溃后恢复 |
| 编译器/解释器 | 源码 → token → AST → 求值/字节码 | `1 + 2 * 3` | 跑一个小程序 |
| CLI/工具库 | 参数 → 解析 → 核心算法 → 输出 | 一个最小输入文件 | 与原工具逐字节一致 |
| 分布式/消息 | 单机 → 复制 → 一致性 → 故障 | 3 个节点 | 杀一个节点仍可用 |

## 反模式

- 从文件树顺序讲(`a.py` → `b.py`)—— 读者无动机。
- 一上来就贴完整类;一个代码块超过 15 行。
- 输出是模型"想象"出来的 —— 必须来自真实运行(`verify_listings.py --fill`)。
- 用读者没学过的术语/数学当已知;正文写"我没验证"。
- 为"完整"而讲每个配置项。工程篇另放。
