# 原文的图:清单、处理、重画

## 为什么图是重点

博客里的图常常是作者花最多功夫的部分:一个手算例子、一条数据流、一张前后对比。文字在为图做旁白。重建时如果只复述文字,读者拿不到最关键的那个"画面"。所以每张图都要有去处。

## 图清单(步骤 2)

逐张看图,写成表(放工作笔记,不进成品):

| 编号 | 原图文件 | 图里画了什么(含关键数字/标签) | 它想让读者明白什么 | 处理 |
|---|---|---|---|---|

"处理"从下面选一个:

- **沿用原图**:原图本身表意清楚——标签完整、版式干净、读者不需要翻译就能看懂(英文的代码名、变量名不算障碍)→ 直接用。这是**默认首选**:作者的图通常经过精心设计,重画既费力又容易走样。图注写自己的结论,附原图链接。
- **沿用 + 补充转写**:原图好但里面的数字读者可能想复制(如 `slot_mapping = [4,5,6,…]`)→ 用原图,并在旁边给一个代码块/表格。
- **重画**:原图需要改才能用时才重画——要加中文标注、信息太密要拆开、几张要合并成一张、或原图有错/含糊 → 自己画成 SVG。
- **转表格/代码块**:图本质是一组数字或一段序列 → 表格或代码块更清楚。
- **舍弃**:图只是装饰、或与正文完全重复、或属于本文不展开的支线 → 写明理由,记进"边界"。

判断"清楚不清楚"要站在没读过原文的读者角度:单看这张图加我的图注,能不能懂?能,就沿用。

## 沿用原图怎么写

```markdown
![图注:一句话结论](https://原站/图.png)
```

或写本地路径(`images/图.png`)。出页时加 `--embed-images`,脚本会把图下载并内嵌,HTML 自包含。图框会自动加白底(原图多为透明底黑线),点击可放大。图总量很大(超过约 20MB)时才改成只链接。

## 重画的规则(只在选了"重画"时)

1. **内容忠实,外观自便。** 数字、标签、箭头关系必须与原图一致,逐个核对;版式、颜色用自己的,不描摹原图。
2. **一张图一个结论。** 图注写成一句完整的结论("块不必连续,块表才是索引"),不是标题("KV 块示意图")。
3. **图里数字要能自洽。** 手算例子里的数字重新算一遍(如 slot 编号 = 块号×块大小 + 块内偏移),发现原图有误就如实在"边界"里指出,不要悄悄改。
4. **图要被正文用到。** 正文在对应台阶里引导读者去看这张图,看什么,看完应有什么发现。
5. **复杂的拆开。** 一张图超过约 12 个元素,就拆成"之前/之后"或"总览 + 局部"。

## 手写 SVG 的规范

每张图一个文件 `figures/figN.svg`,在 Markdown 里这样引用,脚本会内联并套主题色:

```markdown
![图注:一句话结论](figures/fig3.svg "https://原图链接(可选)")
```

要求:

- 根元素只写 `viewBox`(如 `viewBox="0 0 640 260"`),**不写 width/height**,这样能自适应宽度。
- **文件内不要有空行**(会打断 Markdown 的 HTML 块)。
- **不要写 fill/stroke 的具体颜色**,用样式类,这样明暗主题都好看:

| 类 | 用途 |
|---|---|
| `box` | 普通框(白底深描边) |
| `hl` | 高亮框(淡黄,标"当前关注点") |
| `c1` `c2` `c3` `c4` | 四种成对的填充色(蓝/绿/黄/红),区分"属于谁"(如不同请求的 KV 块) |
| `free` | 空闲/灰掉的格子 |
| `line` / `dash` | 实线 / 虚线 |
| `arrow` | 带箭头的线(如 `<path class="arrow" d="M10 10 L100 10"/>`) |
| `acc` / `accf` | 强调色描边 / 填充 |
| 文字类 | `mute`(灰) `b`(粗) `sm`(小) `mono`(等宽) |

- 文字用 `<text>`,对齐用 `text-anchor="middle"`。**先估宽度再画框**:中文约 14px/字,英文/数字约 7.5px/字符;框要比文字宽 16px 以上。
- 色块之上的文字不用设色(样式已处理)。
- 同一篇里图的字号、框高、间距保持一致。

## 样板

**一行格子(块、token、数组):**

```svg
<svg viewBox="0 0 440 90">
<rect class="c1" x="10" y="20" width="60" height="40"/><text x="40" y="45" text-anchor="middle">blk 1</text>
<rect class="c2" x="80" y="20" width="60" height="40"/><text x="110" y="45" text-anchor="middle">blk 2</text>
<rect class="free" x="150" y="20" width="60" height="40"/><text x="180" y="45" text-anchor="middle" class="mute">空闲</text>
</svg>
```

**竖向流程(步骤 + 箭头):** 框高 36、间距 24,箭头 `M cx y1 L cx y2` 用 `class="arrow"`,框内文字起编号 `1) 2) 3)`,与正文编号一致。

**对照(之前/之后):** 同一张图左右两栏,中间一条 `dash` 竖线分隔,栏标题用 `b` 类。

**带旁注:** 旁注用 `mute sm` 文字放在图右侧,用 `dash` 线指回目标框。

## 画完检查

用 Chrome 无头截图(见 SKILL.md),逐张看:文字有没有超出框、箭头是否指对、数字是否与图清单一致。
