# 解剖一篇博客

目标:把文章从"作者写的顺序"还原成"作者想的顺序"。读两遍:第一遍只看它在说什么;第二遍带着下面的问题。

## 必答问题

1. **它在回答什么问题?** 一句话,以疑问句写出。作者往往不直说,要从开头的困惑、反例、"你可能觉得……"里反推。
2. **作者要对抗的是什么直觉?** 大多数好文章是在纠正一个常见的、看似合理的想法。写出那个"天真做法"和它失败的原因。
3. **论证骨架。** 用"因为 A,所以 B;但 B 带来 C,所以 D"的链条写出核心推理,不超过 7 步。每一步标注:是推导、是经验观察、还是断言。
4. **关键例子。** 哪一个例子承担了最大的说服力?它为什么有效?(通常是因为小、具体、能手算。)考虑是否复用,或换一个更小的。
5. **隐含假设。** 作者没说、但结论依赖的前提。读者背景不同,最容易在这里掉队。
6. **术语与前置知识。** 哪些词作者当读者已懂?列出,决定哪些要现场补。
7. **"啊哈"时刻。** 文章里让人豁然开朗的那一句或那一步在哪?重建的整条路都应该通向它。
8. **作者没论证的地方。** 只是断言、靠权威、靠"显然"的部分。记入"边界"。
9. **架构与设计决策(技术文必答)。** 文中的系统/算法由哪几个零件组成?零件之间传的是什么?每条关键边界背后是什么决策:当时的约束、一个显而易见但没被选的做法、选择的代价、约束变了会怎样(设计决策卡,见 `learning-lens.md` §三)。作者没写理由的,标 `[推断]`。
10. **上下贯通。** 每个候选心智模型落在原文哪个例子、哪段代码、哪个数字上?原文最重要的几个细节,各自在为哪个想法服务?对不上的,要么模型提错了,要么细节是支线。
11. **和已知的连接。** 它像读者已经熟悉的哪个东西(同一个机制换了面目)?和哪个常见做法互相拉扯?它依赖什么前提成立、继承自什么更早的想法?只写真实存在的关系。

## 按体裁调整侧重

- **技术/原理类**(算法、系统、论文解读):重点在第 3、4、5、9 问。最容易出问题的是跳步——作者省略的那一步推导,正是读者卡住的地方。能跑的代码和能算的数字都要核验。
- **观点/方法论类**(工程文化、决策、写作、产品):重点在第 2、7 问。核心是一个"看问题的角度",要找到它在什么情形下改变你的决定,给出"用它与不用它"的对比场景。
- **叙事/案例类**(故障复盘、创业经历):重点在因果链。哪些是真正的原因,哪些只是发生在前面?提炼的模型是"从这个故事里学到的判断方式"。
- **系列/长文**:先画出各部分之间的依赖,决定每个台阶对应原文哪几处;不要平均用力。

## 工作笔记格式

写在暂存目录,供自己核验,不进最终稿:

```
问题:
天真做法 / 为何失败:
论证链:(1)… (2)… [标注 推导/观察/断言]
关键例子:
隐含假设:
前置术语:
啊哈时刻:
未论证处:
架构与设计决策:(零件 / 边界 / 决策卡,技术文必填)
贯通表:思想 | 心智模型 | 架构落点 | 原文落点(例子/代码/数字)
连接:(同源异形 / 张力 / 依赖 / 传承,各附一句理由)
候选心智模型:
```
